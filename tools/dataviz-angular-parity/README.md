# dataviz-angular parity harness

Re-derives the Angular ↔ React rendered-markup parity table for the
`@sentropic/dataviz-angular` adapters.

```sh
npm run build                     # the harness reads dist/, not src/
npm run parity:dataviz-angular
```

It renders each Angular adapter through `TestBed` (jsdom) and its React
counterpart through `renderToStaticMarkup`, from the same fixture and the same
props, then compares them:

- **markup diffs** — both DOMs flattened into an order-sensitive list of
  `<tag attr="value" …>` / `#text` entries and diffed position by position;
- **signature diffs** — the same two renders reduced to their user- and
  assistive-technology-visible content (text nodes plus `aria-label`,
  `placeholder`, `title`, `alt`), in document order;
- **bare DS diffs** — a control experiment running the same comparison on the
  *design-system* components with identical inputs. When a case's markup diff
  count equals its bare-DS count, the adapter adds no difference of its own; the
  harness asserts that equality for `HeatmapChart` and `TreemapChart` rather than
  claiming it in prose.

Every count depends on the normalisation in [`normalize.ts`](./normalize.ts),
whose allowlist is documented at the top of that file and covers only
differences that belong to the design-system packages (the `data-st-component`
marker, the `<st-*>` host element, generated ids, `style` formatting, React's
empty `class=""`, class-token order, and the React icon helper's `xmlns` /
`lucide-*`). A stricter or looser allowlist moves the numbers without changing
the conclusions — which is why it is versioned next to the table it produces.

`PARITY_RECORD=1 npm run parity:dataviz-angular` measures and rewrites the table
*without* asserting, to seed the expected counts of a new lot. It is never the
gate — run the command without it once the numbers are in.

The expected counts are asserted, so the harness doubles as a regression gate:
a change that alters what an adapter renders fails it. [`PARITY.md`](./PARITY.md)
is regenerated by the run; update it in the same change as the code that moves a
number.

This directory is not an npm workspace and has no manifest: it resolves `react`,
`react-dom/server`, `@angular/*`, `vitest` and the repository packages from the
root `node_modules`, so it adds nothing to any published package's dependencies.

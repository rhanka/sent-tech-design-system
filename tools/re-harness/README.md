# RE harness — common differential parity harness (Lot L0)

One harness shared by the three reverse-engineering programmes
(bpmn-js, xyflow, JointJS → `@sentropic/graph`). It builds the means of
proof only: no parity entry is implemented here, and no verdict in this
directory upgrades an inventory `status`. A behaviour is `covered` only
when a later lot proves it candidate-against-reference; at L0 the
candidate runner is a stub that declares `unsupported` per entry.

Normative sources (read before changing anything):

- `spec/SPEC_RE_BPMN_JS_PARITY.md` §8 (harness) and §9 (line L0)
- `spec/SPEC_RE_XYFLOW_PARITY.md` §6 (harness) and §8 (line L0)
- `spec/SPEC_RE_JOINTJS_PARITY.md` §4 (contracts), §5 (harness) and §6 (Lot 0)

Reference sources are pinned and read-only in `.ds-scrap/re-sources/`
(`MANIFEST.md` there): bpmn-js 18.31.0, diagram-js 15.28.1, bpmn-moddle
10.3.1, xyflow `@xyflow/react@12.12.0`, `@joint/core@4.3.3`. No network
is used at any step: no CDN, no install.

## Layout

| Path | Content |
|---|---|
| `schemas/` | Versioned JSON schemas (v1) for the fixture formats: `fixture-model` (BPMN XML + derived F1 JSON, xyflow graph JSON, JointJS graph JSON), `fixture-ops` (operation scripts, `undo`/`redo` first-class), `fixture-pointer` (pointer/keyboard scripts in viewport coordinates), `scenario`, `report`. Every fixture is validated against its schema before a run. |
| `contracts/` | Frozen JointJS Lot-0 contracts (display list, camera, magnet descriptor), one versioned schema each, with the spec section and line cited per property. |
| `fixtures/` | Pure-data fixtures shared verbatim by both sides. `bpmn/` holds the first corpus (task, events, gateways, pools/lanes, collapsed subprocess, expanded subprocess, data objects, annotations) plus the `edit-undo` operation script; `xyflow/` holds one fixture per inventory example (93, generated by `gen-xyflow-fixtures.mjs`); `jointjs/` holds graph fixtures; `scenarios/` names, per scenario, the inventory entries it exercises. |
| `src/engines.mjs` | Deterministic reference engines (pure functions of fixture + operations, undo stacks included). No third-party code (clean room). |
| `src/comparators.mjs` | The four comparators in spec strength order: canonical model, event log (names + payload keys, declared id-correspondence), geometry (±1 CSS px; text metrics excluded until the font decision), pixels (secondary signal, per-fixture threshold). What cannot be compared is `unknown`, never asserted. |
| `src/chrome.mjs` | Headless-Chrome driver: `playwright-core` from the repository lockfile when present, then `puppeteer-core`, then the CDP pattern of `packages/graph/tests/golden/cdp-harness.mjs`. Determinism bootstrap: fixed seed, harness-stepped clock and `requestAnimationFrame`, reduced motion forced, animations disabled, viewport 1024×768 at DPR 1. |
| `harness-page.html` | The page both sides run in: in-page engine plus Canvas2D backing-store pixel capture (`document.fonts.ready` awaited, golden harness pattern). |
| `build-bundles.mjs` | Builds local reference bundles from the pinned sources. Committed script; bundles under `bundles/` are build artifacts and are not committed. When a bundle cannot be built offline, the status is recorded `unknown` with the cause (see below). |
| `verify-coverage.mjs` | Scenario → inventory coverage verifier (same style as `tools/re-*/verify.mjs`). Reports the P0/P1 gap per library; fails only with `--strict`. |

## Commands

```bash
node tools/re-harness/src/harness.mjs run             # Node mode: reference against itself
node tools/re-harness/src/harness.mjs run --browser   # same, both sides in headless Chrome
node tools/re-harness/src/harness.mjs selftest        # injected divergences must be detected
node tools/re-harness/src/harness.mjs coverage        # scenario -> inventory gap report
node tools/re-harness/verify-coverage.mjs             # same, gate-style entry point
node tools/re-harness/build-bundles.mjs               # reference bundle status
node --test tools/re-harness/tests/harness.test.mjs   # focused unit tests
npm run re:harness                                    # root alias: browser self-parity
npm run re:harness:selftest                           # root alias: selftest + coverage
```

Every run writes a small deterministic JSON report under
`docs/re/harness-runs/` (`self-parity.json`, `selftest.json`,
`coverage.json`): verdict per scenario and per comparator, keys sorted,
no timestamps, no absolute paths.
